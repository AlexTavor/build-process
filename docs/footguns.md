# Footguns

Traps found while building mlmd: something that looks like it does one thing and does another. An
entry is removed when the trap is gone, not when it is understood.

| # | Looks like | Actually | Anchor | Verified |
| --- | --- | --- | --- | --- |
| F1 | The WorktreeCreate hook gets `base_ref` and `isolation` in its input, as the hooks documentation lists. | Neither field was there, for EnterWorktree with a name or for `--worktree`, on 2.1.165 and 2.1.284. The input had `name`, `cwd`, `session_id`, `transcript_path` and `hook_event_name` (2.1.284 adds `prompt_id`). mlmd's hook has to pick the base branch itself. | [worktree-switching](spikes/worktree-switching.md), "Other observations"; https://code.claude.com/docs/en/hooks.md | 2026-09-30 |
| F2 | An allow rule, or a PreToolUse hook that returns allow, stops Claude Code from asking about EnterWorktree. | On 2.1.284, entering a worktree by path outside `.claude/worktrees/` asks the operator every time, whatever the rules and hooks say. Only bypassPermissions skipped it. Entering by name through the WorktreeCreate hook asks nothing. | [worktree-switching](spikes/worktree-switching.md), sequences a, b and h | 2026-09-30 |
| F3 | A project's hooks run with the same access as its sessions. | From the desktop app's worktree checkbox, the WorktreeCreate hook ran in a process that couldn't read the repository in `~/Documents` ("Operation not permitted"), while sessions in the same folder work. Attempt 3 checks whether this is specific to `~/Documents`. | [desktop-worktree-hook](spikes/desktop-worktree-hook.md), attempt 2 | 2026-09-30 |
| F4 | `claude` in the terminal is the Claude Code the desktop app runs. | On this Mac the terminal's `claude` (Homebrew) was 2.1.165, and the app's bundled CLI was 2.1.284. They behave differently: only 2.1.284 asks before entering a worktree by path (F2). A spike records which one it ran. | [worktree-switching](spikes/worktree-switching.md), "What was done" | 2026-09-30 |
| F5 | An ask rule such as `Bash(git push origin:*)` covers pushes to origin. | It matches only commands that start with that text. `git push`, `git push -u origin`, `git -C <dir> push origin`, `/usr/bin/git push` and `bash -c '...'` ran with no question, on 2.1.165 and 2.1.284, in every mode that let them through. | [trust-enforcement](spikes/trust-enforcement.md), "Verdict" | 2026-09-30 |
| F6 | A project's allow rules in `.claude/settings.json` apply as soon as the file is there. | On 2.1.284 they are ignored until the folder is trusted: `Ignoring 6 permissions.allow entries from .claude/settings.json: this workspace has not been trusted.` Its ask rules and hooks apply either way. | [trust-enforcement](spikes/trust-enforcement.md), "What was done" | 2026-09-30 |
